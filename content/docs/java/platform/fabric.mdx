Use `dev.faststats.fabric.FabricContext` for Fabric mods. Requires Java 21+.

The Fabric SDK also works on [Quilt](https://quiltmc.org), since Quilt can load
Fabric mods. Use the same artifact and setup described below for Quilt mods.

<Callout type="info">
	[Fabric API](https://modrinth.com/mod/fabric-api) must be installed on both
	Fabric and Quilt. Starting with Minecraft 26.1, Quilt can load the original
	Fabric API. On earlier versions, Quilt users have to install [Quilted Fabric
	API](https://modrinth.com/mod/qsl) instead.
</Callout>

<Callout type="info">
	Fabric supports Minecraft versions 1.16.1 to 26.3. Select both the SDK version
	and the exact Minecraft version in your dependency version. You can find the
	available Minecraft version targets in the [Maven
	repository](https://repo.faststats.dev/#/releases/dev/faststats/metrics/fabric/).
</Callout>

**Artifact:** `dev.faststats.metrics:fabric`

```kts
implementation("dev.faststats.metrics:fabric:0.31.0-pre2+mc26.3")
include("dev.faststats.metrics:fabric:0.31.0-pre2+mc26.3")
```

Use both `implementation` and `include`. FastStats is provided as a mod through
jar-in-jar, so `implementation` puts it on your compile classpath and `include`
bundles it into your mod JAR.

The version format is `{sdk-version}+mc{minecraft-version}`, where
`{sdk-version}` is the FastStats SDK version and `{minecraft-version}` is the
exact Minecraft version you are targeting. Each artifact is built for a single
Minecraft version, so pick the one matching your mod.

`0.31.0-pre2` is a pre-release and is published to the snapshots repository
(`https://repo.faststats.dev/snapshots`).

```java
import dev.faststats.ErrorTracker;
import dev.faststats.Metrics;
import dev.faststats.fabric.FabricContext;
import net.fabricmc.api.ModInitializer;

public class ExampleMod implements ModInitializer {
    public static final ErrorTracker ERROR_TRACKER = ErrorTracker.contextAware();

    private final FabricContext context = new FabricContext.Factory("example-mod", "YOUR_TOKEN")
        .errorTrackerService(ERROR_TRACKER)
        .metrics(Metrics.Factory::create)
        .create();

    @Override
    public void onInitialize() {
        // your actual logic
    }
}
```

Pass your mod ID, as defined in `fabric.mod.json` (or `quilt.mod.json` on
Quilt), to `FabricContext.Factory`.

## Client Consent Screen

<Callout type="warn">
	The client consent screen is available starting with `0.31.0-pre2`.
	Pre-releases are published to the snapshots repository, so add
	`https://repo.faststats.dev/snapshots` to your repositories to use it.
</Callout>

Explicit user consent is opt-in. To require it for your mod, call
`requireConsent()` on `FabricContext.Factory`:

```java
private final FabricContext context = new FabricContext.Factory("example-mod", "YOUR_TOKEN")
    .requireConsent()
    .errorTrackerService(ERROR_TRACKER)
    .metrics(Metrics.Factory::create)
    .create();
```

When at least one installed mod requires explicit consent, the client shows a
consent screen on startup. The screen is only shown once. If a mod that requires
explicit consent is installed after mods that did not require it, the screen is
still shown on the next startup.

See [Error Tracking](/java/error-tracking) for configuring error reporting.
